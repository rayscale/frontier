## Usage

```tsx
import { Input } from '@rayscale/frontier'

export function Example() {
  return <Input label="Email" type="email" />
}
```

An input is where someone types or edits a value, so it keeps focus while they type. It renders a native `<input>`, so `type`, `value`, `placeholder`, and the other native attributes work as usual.

## API reference

### Input

Renders a native `<input>` with an optional label, description, error, and symbols. It forwards its ref and the attributes of the input. The table lists the props `Input` adds.

| Prop                        | Type        | Default | Description                                                                  |
| --------------------------- | ----------- | ------- | ---------------------------------------------------------------------------- |
| `description`               | `ReactNode` | —       | Helper text associated with the input for assistive technology.              |
| `error`                     | `ReactNode` | —       | Error message associated with the input. It also marks the input invalid.    |
| `invalid`                   | `boolean`   | `false` | Marks the input as invalid even when no error is shown.                      |
| `label`                     | `ReactNode` | —       | Visible label associated with the input.                                     |
| `leadingSymbol`             | `ReactNode` | —       | Content shown before the value.                                              |
| `leadingSymbolInteractive`  | `boolean`   | `false` | Keeps the leading content available to assistive technology, for a control.  |
| `trailingSymbol`            | `ReactNode` | —       | Content shown after the value.                                               |
| `trailingSymbolInteractive` | `boolean`   | `false` | Keeps the trailing content available to assistive technology, for a control. |

## Accessibility

<Callout title="Give every input a name">
  An input without a name cannot be identified by assistive technology. Pass `label`, and keep that
  text as the name so what is spoken matches what is seen. Without a visible label, set
  `aria-label`.
</Callout>

- The label is tied to the input, so selecting the label focuses the input.
- The description and the error are linked to the input with `aria-describedby` and `aria-errormessage`. The error is announced politely when it appears, and the input reports `aria-invalid`.
- Symbols before and after the value are hidden from assistive technology. Set `leadingSymbolInteractive` or `trailingSymbolInteractive` when a symbol holds a control, and give that control its own accessible name.
- A disabled input uses the native `disabled` attribute and leaves the tab order. A read-only input stays focusable and can be selected.
- The focus ring comes from the focus tokens and shows while the input is being edited.
