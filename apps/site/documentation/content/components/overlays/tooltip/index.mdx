## Usage

```tsx
import { Button, Tooltip } from '@rayscale/frontier'

export function Example() {
  return (
    <Tooltip content="Save your changes">
      <Button>Save</Button>
    </Tooltip>
  )
}
```

Wrap one element in a tooltip to describe it in a few words. The hint appears on hover and on keyboard focus, and it closes when the pointer or the focus leaves. It never holds anything someone must read or act on.

## API reference

### Tooltip

Wraps its child in a `<span>` and shows the hint in a popup rendered in a portal. The popup is linked to the child with `aria-describedby`.

| Prop        | Type                                     | Default | Description                                                                   |
| ----------- | ---------------------------------------- | ------- | ----------------------------------------------------------------------------- |
| `children`  | `ReactElement`                           | —       | The single element that triggers the tooltip. It receives `aria-describedby`. |
| `content`   | `string`                                 | —       | Text shown in the tooltip.                                                    |
| `className` | `string`                                 | —       | Extra class for the wrapper of the trigger.                                   |
| `delay`     | `number`                                 | `350`   | Time before the tooltip shows, in milliseconds.                               |
| `disabled`  | `boolean`                                | `false` | Stops the tooltip from showing.                                               |
| `placement` | `'top' \| 'right' \| 'bottom' \| 'left'` | `'top'` | Preferred side of the trigger. It changes sides when there is no room.        |

## Accessibility

<Callout title="A tooltip is a description, not a name">
  The tooltip text is read as a description of the element. A control that has only an icon still
  needs its own accessible name, such as an `aria-label`.
</Callout>

- The tooltip shows on hover and on focus, so keyboard users get the same hint as pointer users.
- The popup has the `tooltip` role and is linked to the trigger with `aria-describedby`. A description the trigger already has is kept.
- Keep the text short and plain. A tooltip holds no links or controls, and a touch screen may never show it, so do not put essential information in it.
- The trigger must accept `aria-describedby`. A native element or a component of this package does.
